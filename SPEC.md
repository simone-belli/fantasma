# Fantasma — Synthetic Price Simulation Framework

## 1. Purpose

Fantasma is a standalone, installable Python package that generates synthetic price data with known dynamics. Its purpose is to test quantitative models on controlled scenarios where the true data-generating process and its parameters are known, so that expected outcomes can be verified.

It is a separate project from Almanac (the market data library). The two share a common data format so that synthetic and real data are interchangeable in downstream code. Optionally, Fantasma can later be exposed as a data source inside Almanac.

## 2. Design principles

- **Plug and play:** importable by any project; output matches the Almanac data format exactly (asset naming, index conventions, column layout).
- **Extensible by design:** adding a new stochastic model means writing one class. The framework handles time grid, seeding, naming and output.
- **Ground truth available:** hidden state variables (e.g. true drift, OU spread) can be returned alongside prices.
- **Reproducible:** every run is fully determined by its seed.
- **Minimal dependencies:** NumPy and pandas for the core. Estimation libraries (e.g. statsmodels) only as test/dev dependencies.

## 3. Core abstraction: the Process interface

Every model implements a common `Process` interface:

- **Parameters:** declared explicitly, validated on construction, given in annualised units.
- **State variables:** the process declares its state (e.g. log price, drift, spread), its initial values, and which state variables are observable prices versus hidden state.
- **Number of shocks:** how many independent random shocks it consumes per step.
- **Step function:** advances the state by one time step `dt`, given the current state and a vector of random shocks.
- **Asset names:** the observable outputs carry user-supplied asset names.

### Composition

Composite models are built by chaining processes, where the state of one process feeds into another as an input (e.g. an OU process driving the drift of a price process). Composition must be supported generically, not hard-coded per model.

### Noise

Shocks are standard Gaussian in v1, generated by the framework and passed to the step function. The noise generation should sit behind its own abstraction so that fat-tailed or GARCH noise can be added later without changing processes.

## 4. Processes in v1

All prices are simulated in log space; prices are the exponential of log prices.

1. **Random walk:** Gaussian increments with volatility `sigma`. The null scenario with nothing to find.
2. **Drift plus noise:** random walk with constant drift `mu`. The simplest trending case.
3. **Ornstein–Uhlenbeck (mean reverting):** parameters mean level `theta`, half-life (converted internally to speed of reversion `kappa = ln 2 / half_life`), volatility `sigma`. Use the exact discretisation.
4. **Cointegrated system:** N assets driven by K common random-walk factors with loadings, plus stationary OU spreads around them. Parameters: loading matrix, spread half-lives, factor and spread volatilities. Hidden state includes the factors and spreads.
5. **Stochastic mean-reverting drift (momentum-like):** a two-factor model where log price follows drift plus noise, and the drift itself follows an OU process (mean, half-life, vol). Hidden state includes the true drift. This model is built through composition and serves as the reference test of the composition mechanism.

### Possible later extensions (not v1)

- Regime switching between trending and mean-reverting.
- Fat-tailed or GARCH-type noise.
- Arbitrary further stochastic models.

## 5. Time grid

- Internally the simulation runs in abstract time steps, with `dt` derived from the chosen frequency and parameters in annualised units.
- The user supplies a start date and a frequency (e.g. 10-minute, daily) and the number of steps or an end date. The framework maps steps to a pandas DatetimeIndex.
- v1 uses a continuous, regular grid: no trading sessions, holidays or overnight gaps.
- The grid logic must be isolated so that session calendars and overnight gaps can be added later.

## 6. Output format

- **Contract: every simulation produces log returns** (log price differences). One pandas DataFrame per path, indexed by timestamp, one column per asset; one row per step, labelled at the end of the step (the start instant is not a row). This holds for every model, driven models included (their inputs are log returns too).
- Each frame records its start timestamp and starting log prices in `attrs`, so it can be turned back into the exact price path.
- Helpers derive the other quantities: prices and log prices (with the start as a first row) and relative returns; a further helper turns real prices into log returns.
- Column names and index conventions match the Almanac format; prices from the helpers are the wide form of Almanac's close prices.
- Optional flag to return hidden state, as a separate DataFrame on the full grid (start included).
- v1 is close prices only. The output layer is kept separate from the simulation so that OHLC bars and volume can be added later.

## 7. Reproducibility and multiple paths

- Every run takes a seed; identical inputs and seed give identical output.
- The user can request N independent paths in one call. The result is a list of N DataFrames (one per path), with independent but reproducible random streams per path (e.g. NumPy SeedSequence spawning).

## 8. Testing

### Basic checks (required for every process)

- Same seed gives identical output; different seeds give different output.
- Output shape, index and asset names are correct.
- No NaNs, infinities or exploding values for reasonable parameters.
- Parameter validation rejects invalid inputs.

### Parameter-recovery tests (optional, per model)

Each model may optionally provide a recovery test: simulate long seeded paths with known parameters, estimate them back with standard methods, and check estimates fall within tolerance based on expected estimation error, not arbitrary thresholds. This is optional because complex future models may not allow feasible estimation. Reference tests for v1:

- Random walk: realised volatility matches `sigma`.
- Drift plus noise: estimated drift and vol match inputs.
- OU: AR(1) regression recovers mean and half-life.
- Cointegrated system: Johansen or Engle–Granger finds the right number of cointegrating relations and recovers loadings.
- Stochastic drift: a Kalman filter approximately tracks the hidden drift, compared against returned ground truth.

## 9. Out of scope for v1

- Trading sessions, holidays and overnight gaps.
- OHLC bars and volume.
- Non-Gaussian noise and regime switching.
- Direct integration into Almanac.
